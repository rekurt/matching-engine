# matching-engine

**matching-engine** — это высокочастотный движок сопоставления ордеров для криптовалютного спотового рынка, написанный на Rust. Проектировался под требования HFT: нулевые аллокации в горячем пути, lock-free matching на каждый торговый инструмент, бинарный TCP-протокол.

## Для кого

- Биржи и маркетплейсы, которым нужен встраиваемый matching core
- Разработчики, изучающие реализацию стакана ордеров на Rust
- Команды, которым нужен production-ready движок под свой фронтенд

## Возможности

| Возможность | Описание |
|-------------|----------|
| Типы ордеров | LIMIT, MARKET, STOP-LIMIT, STOP-MARKET |
| Time-in-Force | GTC, IOC, FOK |
| Приоритет | Цена → Время (price-time priority) |
| Протокол | Бинарный TCP, фиксированные фреймы |
| Риск-менеджмент | Rate limiting, position limits, price bands |
| Метрики | Prometheus (50+ метрик) |
| Конфигурация | TOML, горячая перезагрузка символов |

## Архитектура за 10 строк

```
me-server  — точка входа: CLI, TOML-конфиг, REST admin (:9091)
    │
    ├── me-io     — TCP-сервер, бинарный кодек, session management
    ├── me-risk   — rate limiting, position limits, price bands
    │
    └── me-engine — оркестратор: диспетчеризует команды по символам
            │
            └── me-book  — стакан ордеров: matching, stop book, events
                    │
                    └── me-core  — примитивы: Order, FixedPrice, Qty, Side
```

Каждый символ обрабатывается на отдельном потоке без мьютексов. Входящий TCP-поток декодируется, проходит риск-проверку и маршрутизируется в нужный `OrderBook`. Исходящие события (`Trade`, `OrderFilled`, `StopTriggered`) отправляются обратно через тот же кодек.
